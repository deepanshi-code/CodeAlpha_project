# CodeAlpha — Machine Learning Internship Projects

Two binary-classification projects completed for the CodeAlpha ML internship:

| Task | Notebook | Question |
|---|---|---|
| 1 | [Task1_Credit_Scoring.ipynb](Task1_Credit_Scoring.ipynb) | Is a loan applicant creditworthy? |
| 2 | [Task2_Disease_Prediction.ipynb](Task2_Disease_Prediction.ipynb) | Does a patient have the disease? |

Each notebook follows the same workflow:
**problem & metric choice → data checks → EDA → stratified train/test split → baselines → cross-validated model comparison → tuning → held-out test evaluation → interpretation → error analysis → limitations.**

## ⚠️ About the data

Both datasets are **synthetic**. They are generated by [`generate_data.py`](generate_data.py) (seed 42, 5,000 rows each).
The labels come from **hand-written rules**:

- **Credit:** `Creditworthy = (Income/1000 − Debts/2000 + 20·Payment_History − Loan_Amount/5000 + Age/10) > 50`
- **Medical:** `Outcome = 1` if at least 3 of 5 thresholds are exceeded (Glucose > 125, BP > 90, BMI > 30, Age > 45, Insulin > 150)

Because the labels are noise-free functions of the features, the scores below are **much higher than you would expect on real data**.
The projects show the *method* (baselines, leakage-safe pipelines, metric choice, error analysis). They are not real-world credit or clinical models.

## Results (held-out test set, 1,000 rows)

### Task 1 — Credit scoring
Main metrics: ROC-AUC and recall on *Not creditworthy* (catching risky applicants).

| Model | Accuracy | ROC-AUC | Recall (not creditworthy) |
|---|---|---|---|
| Majority-class baseline (5-fold CV) | 0.672 | 0.500 | 0.000 |
| Tuned Decision Tree (depth 5) | 0.969 | 0.995 | 0.936 |
| **Logistic Regression** | **0.998** | **1.000** | **0.997** |

Logistic regression wins because the true labelling rule is linear.

### Task 2 — Disease prediction
Main metric: recall on *Disease* (sensitivity), because a missed patient costs more than a false alarm.

| Model | Threshold | Recall | Precision | Missed patients | False alarms |
|---|---|---|---|---|---|
| Majority-class baseline (5-fold CV) | — | 1.000 | 0.551 | — | — |
| Logistic Regression | 0.50 | 0.878 | 0.853 | 67 | 83 |
| Logistic Regression | 0.27 (tuned for recall ≥ 0.95) | 0.953 | 0.792 | 26 | 138 |
| **Random Forest** | 0.50 | **1.000** | **1.000** | 0 | 0 |

Trees beat logistic regression here because the label is a "count the thresholds" rule that a linear model cannot represent.
The perfect Random Forest score is an artefact of the noise-free label. On real data, a perfect score would be a reason to check for leakage.

## How to run

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
python generate_data.py         # optional: data/ already contains the CSVs
jupyter lab
```

Then open either notebook and choose **Run → Run All Cells**.
